# MALT Core v0.0.9

This release consolidates the typed authentication SDK developed throughout
`v0.0.9` release candidates. The previous non-prerelease source tag is
`v0.0.8`. The final tag and GitHub Release identify the exact reviewed merge
commit; this file does not substitute for that source identity.

## Current SDK

Go 1.26.0 or later is required; the `v0.0.8` minimum was Go 1.25.7.

The supported path is typed inputs and coordinates, Prefix/Positional trees,
profile-bound Roots, explicit traversal, and `sdk/authentication` queries,
immutable writers, bounded sessions, candidate batches, and exact receipts.
Applications inject narrow materializer capabilities. Built-in verification
profiles are available through `sdk/authentication/builtin`.

Queries authenticate membership, absence, explicit traversal, and positional
ranges. Complete candidate exports own their buffers. Request-local node and
opening reuse reduces repeated work without trusting a later query's storage.
Batched positional growth commits the final affected subtrees while preserving
canonical Roots; complete snapshots verify shared physical nodes once while
checking metadata and routing at each logical occurrence.

Strict JSON decoding enforces current schemas, required fields, nullability,
byte encodings, and array shapes. Iterator ownership, no-op lineage, exported
buffer ownership, and adversarial shared-node checks have regression coverage.

## Compatibility and migration

`v0.0.8` callers must migrate to the typed SDK. Removed surfaces include semantic
Map/List wrappers and constructors, string resolution, old ProofList and
Resolve/Read APIs, execution/mutation, `sdk/writer`, `sdk/verifier`, the
module-root forwarding facade, and aggregate Store compatibility. Historical
V2/V3 Roots are not decoded or migrated implicitly. Rebuild experimental state
using the current input rules and explicit application migration policy.

Direct cryptographic backend callers must replace the old combined and `Index*`
interfaces with `Committer`, `Prover`, and `Verifier`, and use `commitment.Value`
in place of CID-valued commitments. Proving and `PrepareOpening` now take an
existing caller-selected commitment; commit construction is explicit. See the
[capability migration](../changes/authentication-capabilities.md).

Current Roots use self-describing `V=0`. The package tag does not change Root
versioning or declare production readiness. Relative to `v0.0.9-rc.7`, the
candidate ownership, append, and snapshot refinements do not change current
profile/schema identifiers or valid wire encodings.

The current contracts include `malt.authentication/1` queries,
`malt.authentication/0` complete candidates, `malt.authentication-delta/0`,
`malt.authentication-batch/0`, and `malt.authentication-receipt/0`.
See the [compatibility policy](../policy/compatibility.md) and
[typed migration](../changes/typed-authentication-only.md).

## Distribution and trust boundaries

Core publishes the Go module `github.com/dewebprotocol/malt-core`, protocol
sources, and portable conformance corpus. `malt-ts` separately owns browser
entrypoints, Workers, WASM compilation, reproducible assets, and TypeScript
packaging. Browser consumers must adopt its exact Core-bound package rather
than use historical Core-owned WASM assets with this SDK.

Verification remains relative to the caller-selected Root and intended query.
Candidate roots and materialization receipts are not portable state-transition
proofs, publication attestations, freshness evidence, or trusted-root promotion.
Gateway persistence/publication and local runtime accepted-root policy remain
outside Core.

## Release gates

Follow [the release policy](../policy/releasing.md) on the exact source selected
by the final tag: full Go tests, 386 KZG/IPA tests, vet/build, whitespace and Go
format checks, and an external module importing the supported public packages.
Record the executed commands and results with the final commit in the GitHub
Release. Browser conformance and reproducible archives run in `malt-ts` when it
adopts the published Core tag; downstream module locks and generated assets are
updated and validated separately.
